# Snackbar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `cx.snackbar(Snackbar::new(text).action(label), then)`: a snackbar above the bottom nav and
the FAB, with an optional action. It resolves `ok: true` when the action is tapped, otherwise `ok: false`
with `"timeout"`, `"dismissed"` or `"replaced"`.

**Architecture:**
- A built-in request/response capability `snackbar`/`show` with JSON input, like `dialog`/`confirm`.
- Core: a builder in `dialog.rs`.
- Web: a DOM element on `<body>`.
- Android: an M3 `SnackbarHost` in the scaffold's `Scaffold`.
- iOS: an `@Observable` host drawn as an overlay by `ScaffoldView`.
- No `mobiler-ui` change.

**Tech Stack:** Rust (mobiler-core, mobiler-web/Leptos/web-sys), Compose M3, SwiftUI (iOS 17, Observation).

**Spec:** `docs/superpowers/specs/2026-09-28-snackbar-design.md`

## Global Constraints

- **Wire:**
  - plugin `snackbar`, op `show`
  - input `{"text": String, "action_label"?: String, "duration": "short" | "long"}`
  - output one of `"action"` (ok: true), `"timeout"`, `"dismissed"`, `"replaced"` (ok: false)
- **Durations:** Short 4000 ms, Long 10000 ms.
- **One at a time.** A new show resolves the visible one `"replaced"` (ok: false) before showing.
- **Placement:** the snackbar's bottom edge is above the FAB's top and the bottom nav's top, with a
  12 dp/pt/px gap.
- **Colours:**
  - background `on_surface` (web `var(--ink)`)
  - text `surface` (web `var(--surface)`)
  - action `primary` (web `var(--primary)`)
  - corner radius 4
- **`cx.toast` is unchanged.** Coffee/todo must be pixel-identical to `main`.
- **Repo rules:**
  - don't touch the templates or other demos' shells
  - don't publish
  - the Swift gate is CI
  - per-demo `CARGO_TARGET_DIR`
  - commit bodies via `git commit -F -` with a quoted heredoc

## Review Focus

1. **Replace while visible.** The first `then` must resolve exactly once, with `"replaced"`, and its
   element or view must be gone. Pinned in Task 2 (CDP double-show) and Task 5 (Android double-show).
2. **Timer after action.** Tapping the action and then letting the timer fire must not resolve twice or
   remove a newer snackbar. The web timer checks identity; the iOS timer checks the request id.
3. **No FAB / no tabs.** Placement falls back to the screen bottom plus the safe area, without
   overlapping the home indicator. Pinned in Task 2 by coffee (no FAB) and the CDP rect check.
4. **Screen reader.** Web `role=status aria-live=polite`, iOS announcement, Android M3 live region.
   Pinned in Task 2 (the CDP attribute check).
5. **Theme flips while visible.** Acceptable if a visible snackbar keeps its colours until it's gone
   (≤ 10 s). This is not pinned; the reviewer judges it.

```rust
/// How long a snackbar stays up: Short ≈ 4 s, Long ≈ 10 s.
#[derive(Debug, Clone, Copy, Default, PartialEq, Eq, Serialize)]
#[serde(rename_all = "lowercase")]
pub enum SnackbarDuration { #[default] Short, Long }

/// A snackbar: a short message above the bottom navigation and the FAB, with an optional action
/// ("Undo"). Shown with [`Cx::snackbar`](crate::Cx::snackbar); a newer snackbar replaces a visible one.
#[derive(Debug, Clone, PartialEq, Serialize)]
pub struct Snackbar {
    text: String,
    #[serde(skip_serializing_if = "Option::is_none")]
    action_label: Option<String>,
    duration: SnackbarDuration,
}
impl Snackbar {
    #[must_use] pub fn new(text: impl Into<String>) -> Self { Self { text: text.into(), action_label: None, duration: SnackbarDuration::Short } }
    /// The action button ("Undo"); tapping it resolves `ok: true`.
    #[must_use] pub fn action(mut self, label: impl Into<String>) -> Self { self.action_label = Some(label.into()); self }
    /// Stay up ≈ 10 s instead of ≈ 4 s.
    #[must_use] pub fn long(mut self) -> Self { self.duration = SnackbarDuration::Long; self }
    pub(crate) fn to_input(&self) -> String { serde_json::to_string(self).expect("serialize snackbar") }
}
```

  `confirm_with`:

pub fn snackbar(&mut self, snackbar: Snackbar, then: impl FnOnce(PluginResponse) -> E + Send + 'static) {
    self.plugin("snackbar", "show", snackbar.to_input(), then);
}

```kotlin
/** The scaffold's snackbar host (MainActivity passes it to the M3 Scaffold). `seq` numbers each show,
 *  so a call whose snackbar was dismissed for a newer one can tell it was replaced. */
object SnackbarBus {
    val state = SnackbarHostState()
    var seq = 0
}

/** Built-in `snackbar` capability: input {text, action_label?, duration: short|long}.
 *  ok=true "action" when the action is tapped; else ok=false "timeout" | "replaced" (M3 snackbars
 *  aren't swipeable, so there's no "dismissed" here). A newer snackbar replaces a visible one (M3 would
 *  queue it). */
class SnackbarPlugin : MobilerPlugin {
    override suspend fun handle(op: String, input: String): PluginResponse {
        if (op != "show") return PluginResponse(false, "unknown op '$op'")
        val obj = runCatching { JSONObject(input) }.getOrElse { JSONObject() }
        val label = obj.optString("action_label").ifEmpty { null }
        val duration = if (obj.optString("duration") == "long") SnackbarDuration.Long else SnackbarDuration.Short
        return withContext(Dispatchers.Main) {
            val mine = ++SnackbarBus.seq
            SnackbarBus.state.currentSnackbarData?.dismiss() // one at a time: the older call answers "replaced"
            val result = SnackbarBus.state.showSnackbar(obj.optString("text"), actionLabel = label, duration = duration)
            when {
                result == SnackbarResult.ActionPerformed -> PluginResponse(true, "action")
                SnackbarBus.seq != mine -> PluginResponse(false, "replaced")
                else -> PluginResponse(false, "timeout")
            }
        }
    }
}
```

  Register `"snackbar" to SnackbarPlugin()` next to `"dialog"`,
  and add the imports (`SnackbarHostState`, `SnackbarDuration`, `SnackbarResult`).

  Note that `showSnackbar` holds a mutex. Dismissing the current data first lets the new call proceed
  right away. Verify this on the AVD (Task 5 double-show).

### Task 4: iOS (barbershop)

- [ ] **Step 1: Host + plugin** in `Core.swift`, after `DialogPlugin`:

```swift
/// The snackbar on screen (drawn by ScaffoldView). `nonisolated(unsafe)` like ActiveTheme: touched
/// only on the main thread, from the plugin and the view.
@Observable final class SnackbarHost {
    nonisolated(unsafe) static let shared = SnackbarHost()
    struct Request: Identifiable { let id: Int; let text: String; let action: String?; let seconds: Double }
    var current: Request?
    @ObservationIgnored private var answer: ((String) -> Void)?
    @ObservationIgnored private var nextId = 0

    func show(text: String, action: String?, seconds: Double, answer: @escaping (String) -> Void) {
        finish("replaced")                      // one at a time
        nextId += 1
        current = Request(id: nextId, text: text, action: action, seconds: seconds)
        self.answer = answer
        UIAccessibility.post(notification: .announcement, argument: action.map { "\(text). \($0)" } ?? text)
    }
    /// Resolve the visible snackbar (if `id` matches, when given) and hide it.
    func finish(_ outcome: String, id: Int? = nil) {
        guard let cur = current, id == nil || id == cur.id else { return }
        let a = answer; answer = nil; current = nil
        a?(outcome)
    }
}

@MainActor
enum SnackbarPlugin {
    static func handle(op: String, input: String) async -> PluginResponse {
        guard op == "show" else { return PluginResponse(ok: false, output: "unknown op '\(op)'") }
        let obj = (try? JSONSerialization.jsonObject(with: Data(input.utf8))) as? [String: Any]
        let text = obj?["text"] as? String ?? ""
        let action = (obj?["action_label"] as? String).flatMap { $0.isEmpty ? nil : $0 }
        let seconds: Double = (obj?["duration"] as? String) == "long" ? 10 : 4
        let outcome: String = await withCheckedContinuation { cont in
            SnackbarHost.shared.show(text: text, action: action, seconds: seconds) { cont.resume(returning: $0) }
        }
        return PluginResponse(ok: outcome == "action", output: outcome)
    }
}
```

  Route it with `case "snackbar": return await SnackbarPlugin.handle(op: op, input: input)` next to
  `"toast"`. The `withCheckedContinuation` closure touches the `nonisolated(unsafe)` static, which is
  the pattern that compiled for `DialogPlugin`. If the compiler still objects, wrap it in
