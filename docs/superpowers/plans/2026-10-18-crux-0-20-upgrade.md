# crux 0.20 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every Mobiler library, demo and the CLI template move to `crux_core 0.20.0` / `facet =0.46.5`, the app's
codegen generates its UniFFI bindings itself, and `mobiler upgrade --apply` carries an existing app over with no
hand edits.

**Architecture:** Two PRs (ADR-0009). PR 1 (libraries): bump crux/facet in the root workspace and `mobiler-web`,
migrate every demo (they use path deps, so they move with the libraries), prove the generated Kotlin/Swift are
byte-identical, publish ui 0.32 → core 0.47 → web 0.47. PR 2 (CLI 0.70): port barbershop's codegen to the template,
pin the published core, widen `mobiler upgrade`'s dependency step, add ADR-0054/0055 with mutation-proven
conformance tests.

**Tech Stack:** Rust (crux_core 0.20, facet 0.46.5, uniffi 0.29.4 library-mode bindgen, cargo_metadata 0.19, camino 1),
the CLI's `upgrade.rs`, xtask conformance tests.

**Spec:** `docs/superpowers/specs/2026-10-18-crux-0-20-upgrade-design.md`

## Global Constraints

- `crux_core = "0.20.0"` (workspaces), `"0.20"` (mobiler-web); `facet = "=0.46.5"`; `uniffi = "=0.29.4"` stays.
- Versions: mobiler-ui 0.32.0, mobiler-core 0.47.0, mobiler-web 0.47.0, CLI 0.70.0.
- Codegen deps: `cargo_metadata = { version = "0.19", optional = true }`, `camino = { version = "1", optional = true }`;
  `codegen` feature lists `"uniffi/bindgen"`, `"dep:cargo_metadata"`, `"dep:camino"` and no `"crux_core/cli"`.
- Generated Kotlin and Swift (types + bindings) must be byte-identical to the pre-upgrade output. A types diff stops
  all work until the maintainer has seen it; a bindings diff is fixed in the helper.
- Upgrade edits only the lines in spec §3's table; any other framework pin is reported, never edited.
- `ffi.rs` is not changed. `uniffi` is not bumped. No BoltFFI.
- Build targets on `/media/zmilan/data2/cargo-target-<name>` (never the shared `/media/zmilan/data2/cargo-target`);
  JDK 21 (`/usr/lib/jvm/java-21-openjdk-amd64`); emulator `mobiler_pixel7` on `-port 5560`, `--device emulator-5560`
  (a real phone may be attached; never install on it).
- Wait on builds with `run_in_background` or `wait <pid>`; never `pgrep -f` / `until grep` loops; never `find /`;
  don't wipe `~/.gradle`.
- Commit messages via `git commit -F <file>`. Every crates.io publish and the `v0.70.0` tag need the maintainer's OK.

## Review Focus

1. An app whose workspace pins crux in table form (`crux_core = { version = "0.18.0", ... }`): upgrade must report
   the hand edit, not skip silently or half-edit. Test in Task 6.
2. An app whose `codegen` feature is written on one line (`codegen = ["crux_core/cli", ...]`): reported, not
   mangled. Test in Task 6.
3. Running `mobiler upgrade` (no `--apply`) on a 0.69 app: prints every pending manifest edit, writes nothing. Test
   in Task 6.
4. A manifest with CRLF line endings (an app edited on Windows): edits keep CRLF. Test in Task 6.
5. Codegen under a custom `CARGO_TARGET_DIR` (how `mobiler dev` runs it): the helper must find the library there,
   not in `./target`. Verified in Task 3 step 4 and Task 8.

### Task 6: `mobiler upgrade` moves the framework's pins

**Files:**
- Modify: `mobiler/src/upgrade.rs` (replace `bump_core_dep` and the `deps*` fields of `Report`; tests in its
  `mod tests`).

**Interfaces:**
- Produces (all in `upgrade.rs`):
  - `fn template_pin(template: &str, dep: &str) -> Option<String>` — reads `dep = "X"` from an embedded template
    file (`Cargo.toml.tmpl` for `crux_core`, `shared/Cargo.toml.tmpl` for `mobiler-core`); replaces
    `template_core_version`.
  - `fn set_pin(content: &str, dep: &str, want: &str) -> Edit` — string-form `dep = "X"` only.
  - `fn migrate_codegen_feature(content: &str) -> Edit` — replaces a line that is exactly (trimmed)
    `"crux_core/cli",` with three lines `"uniffi/bindgen",` / `"dep:cargo_metadata",` / `"dep:camino",` at its indent.
  - `fn add_codegen_deps(content: &str) -> Edit` — after the line starting `uniffi = {` that contains
    `optional = true`, inserts the missing ones of the two Global-Constraints dep lines.
  - `enum Edit { Changed(String, String /*what*/), Unchanged, Unrecognised(String /*hand-edit note*/) }`.
  - `fn foreign_pins(root: &Path, skip: &[&Path]) -> Vec<String>` — every other `Cargo.toml` under the app root
    (skip `target/`, `node_modules/`, `.mobiler/`) with a `crux_core`, `mobiler-core` or `mobiler-web` pin that
    differs from the template's; one note each: `"<path>: <dep> <have> → <want> (edit by hand)"`. Any `facet`
    dependency in any app manifest (the template declares none) gets the note `"<path>: declares facet <have>;
    it must be =0.46.5 to match crux_core 0.20 (edit by hand)"` (spec §3).
  - `Report.deps: Vec<String>` (applied), `Report.deps_would: Vec<String>` (review run), `Report.deps_notes:
    Vec<String>`; printed one per line as `deps: …` in the existing report style.
- Every edit preserves the file's line endings (detect `\r\n`).

- [ ] **Step 1: Write the failing tests** in `upgrade.rs` `mod tests`:
  - `set_pin_moves_a_string_pin_and_is_a_no_op_at_target` — `crux_core = "0.18.0"` → `Changed`, text has
    `crux_core = "0.20.0"`; at `0.20.0` → `Unchanged`.
  - `set_pin_reports_a_table_form_pin` — `crux_core = { version = "0.18.0", features = ["x"] }` → `Unrecognised`
    whose note names `crux_core` and `0.20.0`. (Review Focus 1)
  - `codegen_feature_migrates_the_multiline_form_once` — template-0.69 `codegen = [\n    "crux_core/cli",\n ...]` →
    three lines at 4-space indent, no `crux_core/cli`; applied twice → second `Unchanged`.
  - `codegen_feature_on_one_line_is_reported` — `codegen = ["crux_core/cli", "uniffi"]` → `Unrecognised`.
    (Review Focus 2)
  - `codegen_deps_are_added_after_uniffi_once` — both lines appear right after the `uniffi` line; re-run
    `Unchanged`; no `uniffi` line → `Unrecognised`.
  - `crlf_manifests_keep_crlf` — each edit on a `\r\n` input yields only `\r\n` endings. (Review Focus 4)
  - `upgrade_moves_a_069_app_and_rerun_is_a_no_op` — scaffold with the current templates, rewrite its manifests to

  - `other_crates_pins_are_reported_not_edited` — add `app-core/Cargo.toml` with `crux_core = "0.18.0"` and
