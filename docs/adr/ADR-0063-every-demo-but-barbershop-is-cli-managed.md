# ADR-0063: Every demo but barbershop (Saldo, coffee, todo, fullstack-todo's mobile app) is CLI-managed and equals the current template; every CLI PR that changes a template shell runs `mobiler upgrade --apply` in each, and a conformance test fails until it does

Status:        Accepted
Date decided:  2026-10-20
Deciding PRs:  #308
Supersedes:    ADR-0060
Code anchor:   demos/{saldo,coffee,todo,fullstack-todo/mobile}/.mobiler/ (version stamp + base snapshot), .claude/skills/release-cli/SKILL.md (the upgrade step)
Conformance:   xtask/tests/adr_conformance.rs::adr_0063_every_demo_but_barbershop_is_cli_managed

## 1. Context (The Problem)

ADR-0060 made Saldo CLI-managed: its shells equal the template, its `.mobiler/` is committed, and a strict test fails
until each shell-changing CLI PR upgrades it. The other demos stayed hand-copied shells far behind the template. They
still had the Android theme bug until #303 fixed it file by file. The maintainer asked to bring them up to date
(2026-10-20), and chose the same strict guard for them: "Strict, like Saldo".

Barbershop stays out: it is the reference shell the template is ported from (ADR-0015), so it can't be generated
from it.

## 2. Hypothesis

If coffee, todo and fullstack-todo's mobile app are regenerated by `mobiler new` + `mobiler plugin add`, keep only
what is theirs, and are held to ADR-0060's test, then no demo but barbershop can lag the template by more than one PR.
Every demo also exercises `mobiler upgrade` on each shell change.

What each demo keeps, from a commit-by-commit audit of its shells (coffee 126, todo 97, fullstack-todo 94 commits):
- **Coffee:** its iOS app icon, its five bundled plugins, its terracotta theme (already in its Rust; it renders only
  in light mode, so no palette is needed).
- **Todo:** nothing beyond its names; its indigo theme is in its Rust, and its saved state keeps the same key.
- **fullstack-todo:** its iOS display name `FullstackTodo` (written by the CLI), and `[ios] local_network = true`
  (ADR-0064) for its `http://localhost:3000` server.

What the maintainer gave up or moved (2026-10-20):
- Coffee's hand-uncommented `VIBRATE`: the template now declares it for `cx.haptic`.
- Coffee's iOS landscape: dropped (portrait like the template).
- Coffee's iOS UI test: moved to barbershop (`FadehouseUITests`), since the template can't carry a second Xcode
  target.

### 2.1. Refutation Conditions

- **Condition 1: each demo's base snapshot is the current template.** It holds every template file, except the ones
  an app owns. Its version stamp equals the CLI's.
  - **Validation Metric:** `adr_0063_every_demo_but_barbershop_is_cli_managed`.
- **Condition 2: no demo's shell code is edited by hand.** Each shell file must equal the template apart from three
  things:
  - plugin insertions above comment anchors, each line equal to a used bundled plugin's rendered insertion (read
    from its manifest);
  - the display name the CLI wrote, exactly, once;
  - the blocks the demo's `mobiler.toml` switches.

  Plugin sources must equal the bundled ones. `Info.plist` and `settings.gradle.kts` must equal the template.
  - **Validation Metric:** the same test.

## 3. Considered Options & Rationale for Refutation

- **Option A: upgrade the demos at each release, with no CI gate** `[recorded: the maintainer's choice between the two, 2026-10-20]`
  Rejected: "Strict, like Saldo". Without a gate they lag between releases, as they did before.
- **Option B: leave the demos as they were** `[recorded: the spec, 2026-10-20]`
  Rejected. They had drifted far enough to carry a fixed bug (the Android theme).

## 4. Decision & Rationale for Corroboration

Option: the four demos are CLI-managed under one test, the Saldo test generalised over a table of (dir, package,
name, display name, local network). The release-cli skill's step upgrades all four.

**Mutation proof:** the invariant was broken four times on purpose, on the newly managed demos. The test failed each
time; the file was restored, and the test passed again.
- A comment line was added to coffee's `MainActivity.kt` (`ADR-0063: …/coffee/MainActivity.kt is edited by hand …`).
- `PhotoPipeline.swift` was removed from todo's base
  (`ADR-0063: the template has iOS/Sources/PhotoPipeline.swift, demos/todo's base doesn't: …`).
- fullstack-todo's local-network block was switched off while its `mobiler.toml` asks for it
  (`ADR-0063: …/fullstack-todo/mobile/iOS/project.yml is edited by hand (line 70: # off: NSAppTransportSecurity:) …`).
- `"foo" to FooPlugin(),` was written above coffee's Core.kt plugin anchor (`… Core.kt is edited by hand …`).

ADR-0060's own mutations still apply to Saldo, which is one row of the same test.

## 5. Consequences (Positive and Negative Predictions)

- **Positive:** every demo but the reference runs the current shells, and four apps exercise `mobiler upgrade` in every
  shell-changing CLI PR.
- **Negative:** each such PR upgrades four demos (one command each), or CI fails.
- **Negative:** a demo can't carry a shell experiment of its own. A behaviour it needs goes into the template, a
  plugin or a `mobiler.toml` option first, as coffee's haptics permission and fullstack-todo's local networking did.
- **Negative:** coffee lost iOS landscape, and its UI test now runs on barbershop. Its camera prompt is now the scanner
  plugin's ("Scan barcodes and QR codes."), though it also takes photos.
- **Negative:** an allowed plugin line is accepted above any anchor, in any file, any number of times; the check pins
  what may be inserted, not where. A demo that switches a `[deep_links]` block off isn't supported by the test yet.
